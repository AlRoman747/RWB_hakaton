# Архитектурные решения и риски

## Решения

- **Минимальный контур:** PostgreSQL 16, одноразовый Python pipeline и опциональный test-контейнер в одном Docker Compose. Нет очередей, Kubernetes, микросервисов и тяжёлых ORM.
- **Три схемы:** неизменяемый источник `raw`, командная модель `core`, витрины `mart`. Это сохраняет контракт задания и разделяет ответственность агентов.
- **Атомарная полная перезагрузка:** одна транзакция и advisory lock важнее сложного инкрементального механизма для фиксированного набора CSV. Предыдущая успешная версия сохраняется при сбое.
- **Наблюдаемый успех:** manifest хранит `run_id`, SHA-256 и количество строк. Ненулевой код выхода является сигналом ошибки для Compose и CI.
- **Воспроизводимость:** зафиксированы версии Python-образа, PostgreSQL и зависимостей; CSV не коммитятся, повторные запуски и чистая база проходят один и тот же путь.
- **Безопасность локального контура:** пароль берётся только из `.env`, порт БД слушает `127.0.0.1`, Python-контейнеры работают от непривилегированного пользователя и read-only rootfs.
- **Интеграция без переписывания:** модель и запросы подключаются файлами в предсказуемом порядке. Инфраструктура не меняет их бизнес-логику.

## Оставшиеся риски

- Полная перезагрузка удерживает блокировки `raw`; при больших данных понадобятся staging/partition swap и оценка времени простоя.
- Скачивание использует публичную ветку Olist без заранее зафиксированных хешей. Хеши фиксируются в manifest после загрузки, но для строгого воспроизведения конкретного релиза нужен неизменяемый артефактный источник.
- Идемпотентность `model/` и `queries/` обеспечивает владелец SQL; runner гарантирует транзакционность и порядок, но не исправляет неидемпотентный DDL.
- На момент инфраструктурной интеграции бизнес-SQL и его контрольные тесты отсутствуют, поэтому аналитические показатели этим контуром не подтверждаются.
- Настроены health check и CI, но нет резервного копирования, мониторинга, управления миграциями и внешнего секрет-хранилища. Для эксплуатации за пределами хакатона они обязательны.
- Публичная аналитическая СУБД потребует отдельной настройки TLS, ролей и сетевой политики; текущий проброс порта предназначен только для локальной работы.
